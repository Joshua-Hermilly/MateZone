Architecture

Architecture de MateZone

Une structure hexagonale (ports et adaptateurs) qui sépare le client, la couche commune, le serveur et la persistance. La version présentée est celle de la branche pre-releases-beta, la plus aboutie.

01

Vue d'ensemble

Couche client (MVC)

  • Contrôleur : gère les interactions de l'utilisateur
  • IHM : interface JavaFX avec FXML
  • Métier client : logique côté client

Couche commune

  • DTO : objets de transfert de données
  • Protocol : énumérations et contrats

Couche serveur

  • WebSocket : protocole de communication
  • Service : logique métier serveur
  • Repository : accès aux données

Persistance

  • Base MySQL : utilisateurs, messages et groupes
02

Structure des modules

Le rôle de chaque module et l'arborescence de ses fichiers.

Module client

Responsabilités

  • Gestion de l'interface utilisateur
  • Traitement des événements utilisateur
  • Communication avec le serveur via WebSocket
  • Logique métier côté client

Module serveur

Responsabilités

  • Gestion des connexions WebSocket
  • Logique métier serveur
  • Persistance des données
  • Authentification des clients
03

Patrons de conception

Des patrons reconnus, utilisés pour garder un code de qualité.

🏗️

Architecture hexagonale

Séparation nette entre la logique métier et les adaptateurs externes : base de données, interface, réseau.

Avantage : un code facile à tester et à maintenir.

🏛️

Modèle MVC

Modèle, vue et contrôleur organisent le code côté client.

Avantage : une interface découplée de la logique.

🗄️

Pattern Repository

L'accès aux données passe par des interfaces propres à chaque entité métier.

Avantage : la source de données se change facilement.

📦

Pattern DTO

Des objets de transfert sérialisés en JSON structurent les échanges entre client et serveur.

Avantage : une communication structurée.

🔌

Pattern Adapter

Les WebSockets sont adaptés aux interfaces métier pour découpler la technologie de communication.

Avantage : une technologie réseau interchangeable.

🎯

Injection de dépendances

Les dépendances sont fournies aux composants plutôt que créées par eux.

Avantage : un couplage réduit entre les composants.

04

Flux de communication

Comment un message circule entre le client et le serveur.

Envoi d'un message

  1. L'utilisateur saisit un message dans l'IHM.
  2. Le contrôleur capture l'événement.
  3. Le métier client valide le message.
  4. L'adaptateur WebSocket envoie le DTO.
  5. Le serveur WebSocket le reçoit.
  6. Le service le traite et le sauvegarde en base.
  7. Le message est diffusé aux clients connectés.

Réception d'un message

  1. Le serveur diffuse un nouveau message.
  2. L'adaptateur WebSocket client reçoit le DTO.
  3. Le métier client traite l'événement.
  4. Le notifieur met à jour l'IHM.
  5. L'interface affiche le nouveau message.
  6. L'utilisateur voit la mise à jour en temps réel.
05

Avantages de l'architecture

Pourquoi MateZone utilise une architecture hexagonale.

🧪

Testabilité

  • Chaque couche se teste séparément
  • Dépendances externes remplaçables par des doublures
🔧

Maintenabilité

  • Responsabilités bien définies
  • Faible couplage entre les modules
📈

Évolutivité

  • Nouveaux adaptateurs possibles
  • Services métier extensibles
🔄

Réutilisabilité

  • Logique métier indépendante
  • Interfaces standardisées
