Base de données

Base de données MateZone

La structure MySQL qui alimente MateZone, avec le moteur InnoDB et l'encodage utf8mb4.

01

Vue d'ensemble

MySQL stocke de façon fiable les utilisateurs, les groupes et les messages.

👥

Comptes utilisateurs

  • Identifiants uniques
  • Mots de passe hashés
  • Image de profil personnalisée ou par défaut
💬

Historique des messages

  • Messages horodatés
  • Rattachés à un groupe
  • Auteur identifié
🏷️

Groupes

  • Groupes publics ou privés
  • Membres avec un rôle
  • Créateur du groupe conservé
02

Configuration et connexion

Ce qu'il faut pour se connecter à la base.

Configuration requise
ParamètreValeur
SGBDMySQL 8.0+
EncodageUTF-8 (utf8mb4)
MoteurInnoDB
Port par défaut3306

Sécurité : le fichier config.properties contient les identifiants de la base et ne doit jamais être versionné. Copiez config.properties.example vers config.properties, puis renseignez vos paramètres.

03

Structure des tables

La structure réelle de la base, telle que définie dans le script MateZone.sql.

🖼️ Table default_images

Les images de profil par défaut. Une seule copie binaire est conservée par image.

Colonnes de la table default_images
ChampTypeContraintesDescription
idINTPRIMARY KEY, AUTO_INCREMENTIdentifiant de l'image
nomVARCHAR(50)UNIQUE, NOT NULLNom de l'image
img_dataMEDIUMBLOBNOT NULLDonnées binaires de l'image
created_atTIMESTAMPDEFAULT CURRENT_TIMESTAMPDate de création

👤 Table clients

Les comptes utilisateurs, avec leur mot de passe hashé et leur image, personnalisée ou par défaut.

Colonnes de la table clients
ChampTypeContraintesDescription
idINTPRIMARY KEY, AUTO_INCREMENTIdentifiant unique du client
pseudoVARCHAR(255)UNIQUE, NOT NULLPseudo de connexion
mdpVARCHAR(255)NOT NULLMot de passe hashé
custom_img_dataMEDIUMBLOBNULLImage de profil personnalisée
default_image_idINTDEFAULT 1, FK default_images(id)Image de profil par défaut
created_atTIMESTAMPDEFAULT CURRENT_TIMESTAMPDate de création du compte

🏢 Table groupes

Les groupes de discussion créés par les clients.

Colonnes de la table groupes
ChampTypeContraintesDescription
idINTPRIMARY KEY, AUTO_INCREMENTIdentifiant unique du groupe
nomVARCHAR(150)UNIQUE, NOT NULLNom du groupe
typeVARCHAR(20)NOT NULL, DEFAULT 'groupe'Type de groupe (groupe ou prive)
cree_parINTFK clients(id)Créateur du groupe
cree_leTIMESTAMPDEFAULT CURRENT_TIMESTAMPDate de création du groupe

💬 Table messages

Tous les messages envoyés dans chaque groupe.

Colonnes de la table messages
ChampTypeContraintesDescription
idINTPRIMARY KEY, AUTO_INCREMENTIdentifiant unique du message
groupe_idINTFK groupes(id), NOT NULLGroupe destinataire
expediteur_idINTFK clients(id), NOT NULLClient qui a envoyé le message
contenuTEXTNOT NULLContenu du message
envoye_leTIMESTAMPDEFAULT CURRENT_TIMESTAMPDate et heure d'envoi

🔗 Table membres_groupes

Le lien entre clients et groupes (relation N:N), avec un rôle.

Colonnes de la table membres_groupes
ChampTypeContraintesDescription
idINTPRIMARY KEY, AUTO_INCREMENTIdentifiant de l'enregistrement
groupe_idINTFK groupes(id), NOT NULLGroupe concerné
client_idINTFK clients(id), NOT NULLClient membre du groupe
roleVARCHAR(50)DEFAULT 'membre'Rôle dans le groupe
date_adhesionTIMESTAMPDEFAULT CURRENT_TIMESTAMPDate d'adhésion
04

Relations entre les tables

  • Un client peut créer plusieurs groupes (1:N via groupes.cree_par).
  • Un client peut appartenir à plusieurs groupes (N:N via membres_groupes).
  • Un groupe contient plusieurs messages (1:N via messages.groupe_id).
  • Un client peut envoyer plusieurs messages (1:N via messages.expediteur_id).
  • Plusieurs clients peuvent partager la même image par défaut (1:N via default_image_id).

06

Performance et intégrité

⚡

Index

  • messages.groupe_id : récupération rapide par groupe
  • messages.expediteur_id : récupération par expéditeur
  • clients.pseudo : index implicite via la contrainte UNIQUE
  • membres_groupes(groupe_id, client_id) : index implicite via UNIQUE
🔒

Contraintes d'intégrité

  • Clés étrangères : cohérence référentielle
  • Contraintes UNIQUE : pas de doublons
  • Contraintes NOT NULL : données obligatoires
