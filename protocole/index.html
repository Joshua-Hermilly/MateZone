Protocole

Protocole WebSocket

Le protocole de communication en temps réel entre le client et le serveur : des événements au format JSON, décrits par une classe de transfert et une énumération.

01

Vue d'ensemble

📦

ChatEventDTO

La classe de transfert qui structure tous les événements de chat échangés en JSON, dans un format standard pour chaque échange entre le client et le serveur.

🏷️

EventEnum

L'énumération qui définit les types d'événements et les clés de données attendues pour chacun, afin de garder des messages cohérents.

02

Structure d'un ChatEventDTO

Trois champs : le type, une table de données et une liste facultative d'autres événements.

type

Le type d'événement, défini par EventEnum. Il détermine les clés de données requises.

data

Une table clé-valeur avec les données propres à l'événement, selon son type.

lstEventDTO

Une liste facultative d'événements, utilisée surtout pour MESSAGE_LIST.

06

Gestion des erreurs

Erreurs possibles

  • Authentification échouée
  • Données manquantes
  • Format JSON invalide
  • Type d'événement non reconnu
  • Erreur serveur

Validation

  • Structure JSON correcte
  • Présence du champ type
  • Clés requises selon EventEnum
  • Types de données cohérents

Bonnes pratiques

  • Toujours vérifier le type d'événement
  • Gérer les erreurs côté client
  • Utiliser les constructeurs adaptés
  • Valider les données avant l'envoi

Important : tous les échanges doivent respecter la structure ChatEventDTO. Un message mal formé est rejeté par le serveur avec un événement ERROR qui contient le détail.
